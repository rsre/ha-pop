# Publication and privacy

The public repository contains generic examples and integration source. Runtime panel tokens, deployment-specific documentation, browser profiles, and original operational snapshots do not belong in Git or release archives.

## Audit scope

The audit checks source files, historical file contents and filenames, commit messages, and author/committer metadata. It looks for private-key blocks, access tokens, literal credentials, deployment addresses, personal filesystem paths, and site-specific configuration.

No private-key material, access token, or literal password was detected in the initial 14-commit history. Deployment details appeared in ten historical commits; author metadata also identified the developer. These require redaction even though they are not authentication secrets. Repository-owner references in the chosen public GitHub URLs and `codeowners` are intentionally retained for HACS metadata.

Private source snapshots are ignored under `.local/`. The original Git recovery bundle is stored outside the checkout. Release exports exclude `.git`, `.local`, virtual environments, generated bytecode, and other build output. The public-source export contains no Git history.

Pattern matching cannot prove the absence of every possible sensitive value. Review future changes before publishing, especially configuration examples and screenshots.

## Publish

1. Review the sanitized source and rewritten history locally. Do not push the private recovery bundle or `.local/` contents.
2. Choose a source license before publishing; this repository does not grant one implicitly.
3. Set the GitHub repository description and Home Assistant/HACS topics.
4. Push the reviewed source to the chosen repository. The remote branch was confirmed to contain the previous commits. Coordinate replacement of that history and use an explicit force-with-lease against the remote's expected old revision. No remote history is rewritten automatically by this cleanup.
5. Confirm CI's tests, hassfest, and HACS validation pass.
6. Add the repository as a HACS custom Integration repository, download the integration, restart HA, and perform the UI setup and live wake/sleep/doorbell checks.

A clean source archive can be generated with:

```sh
python3 homeassistant/build_release.py
```

The generated `dist/ha-pop-public-source-<version>.zip` has no Git metadata. The smaller `dist/ha-pop-<version>.zip` contains only the installable integration. The existing Pi and Home Assistant installations are not changed by building these packages.

## Review and push

Review the committed package before pushing. The private `.local/history-rewrite-original.json` records the original branch revision and recovery-bundle path. To replace the existing remote branch, use an explicit lease against that recorded old revision rather than a plain force push. A remote update made since the check will cause the lease to reject the push.
