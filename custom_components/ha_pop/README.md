# Home Assistant integration

HA Pop Panel provides a panel device with Wake, Sleep, and Show doorbell buttons, a timestamped popup-command entity, and a native Lovelace dashboard. All integration setup uses the Home Assistant UI.

## Install through HACS

The source must be published to the GitHub repository before HACS can download it.

1. Open HACS → Custom repositories.
2. Add `https://github.com/rsre/ha-pop`, category **Integration**.
3. Download **HA Pop Panel** and restart Home Assistant.
4. Open Settings → Devices & services → Add integration → **HA Pop Panel**.
5. Enter the Pi hostname (for example `panel.local`), port `8765`, and shared token. Select the doorbell camera and an unused dashboard path, such as `ha-pop-panel`.

The token is generated by the [Pi installer](../../panel/README.md). On the Pi, use its desktop file manager to open `~/.config/ha-panel/remote-token` with hidden files visible, then copy its contents into the setup form. You do not need an SSH session to Home Assistant. Keep this file private.

The connection check uses authenticated `GET /health`. It verifies the token and persistent panel ID without waking the screen.

## Controls and automation

The integration creates three button entities on the panel device:

| Button | Effect |
| --- | --- |
| Wake | Wake the screen and hold it awake for at least five minutes |
| Sleep | Cancel the wake hold and sleep immediately, retaining guarded touch wake |
| Show doorbell | Wake, return to the panel dashboard, and open its selected camera |

Use `button.press` with the appropriate entity in the automation editor. Entity IDs depend on the configured device name and can be renamed through HA. They are not hardcoded in the integration.

For a device named **Wall Panel**, the automation action to wake and show the camera is:

```yaml
actions:
  - action: button.press
    target:
      entity_id: button.wall_panel_show_doorbell
```

Use `button.wall_panel_wake` to wake without opening video, or `button.wall_panel_sleep` to sleep. Select your device's actual button in the editor. Automations call these buttons directly. The [doorbell blueprint](blueprints/doorbell.yaml) uses the same direct action.

For an event-based doorbell, import the [doorbell blueprint](blueprints/doorbell.yaml) in Settings → Automations & scenes → Blueprints, using this URL:

```text
https://github.com/rsre/ha-pop/blob/main/custom_components/ha_pop/blueprints/doorbell.yaml
```

Create an automation from it, choose the doorbell event entity, ring event type, and the panel's **Show doorbell** button. The resulting automation is editable through the normal UI. Binary-sensor doorbells can use a normal state-triggered UI automation that presses the same button.

Show doorbell calls the Pi's authenticated `/doorbell` endpoint. It wakes the display and uses local browser control to return to the URL configured on the Pi, even if another dashboard or page is open. The dashboard consumes a fresh popup request once it is ready. Repeated rings keep an already-open video card intact. The integration also records a popup event after the Pi accepts the command. Talk requires an explicit user action. The popup remains open until dismissed.

Connection errors identify the configured panel address and suggest checking hostname resolution. If HA cannot resolve the Pi's hostname, use its LAN IP in Reconfigure. Authentication errors request the panel token; browser errors identify the kiosk service or dashboard URL to check.

## Dashboard and updates

The dashboard is registered at `/<chosen-path>/home`. Configure this URL on the Pi. The layout and entity mappings are editable in the dashboard UI; updates and integration reloads preserve saved edits. The integration manages the dashboard's sidebar registration and URL, so remove it through Devices & services rather than dashboard management.

The bundled frontend loads automatically. It needs no manually registered JavaScript resource, `/config/www` copy, or separate frontend download. See the [dashboard guide](docs/dashboard.md) for controls and layout.

Use Reconfigure on the integration to change its address, port, name, or token. Change camera and other card mappings through the dashboard editor. Moving the dashboard to a new URL requires removing and re-adding the integration. HACS handles code updates; restart HA and reload the browser afterward.

## Local network and removal

The Pi endpoint uses an authenticated local HTTP connection. Keep it on a trusted LAN and do not forward its port to the internet. The shared token is stored in the HA config entry and the Pi's private token file, never in the frontend or repository. Setup does not follow redirects with the credential. The persistent panel ID prevents an address change from silently associating the integration with a different device.

Removing or disabling the integration removes its entities and sidebar registration. Saved dashboard content is retained so edits survive reconfiguration and reloads. Remove associated automations separately through the UI. The Pi continues its normal local sleep behavior.

## Validation

The offline suite covers authenticated HTTP commands, configuration flow branches, duplicate identities, foreign-dashboard protection, preservation of dashboard edits, setup failure cleanup, command serialization, and browser popup handling. Lifecycle and flow tests use Home Assistant API doubles; they do not replace a live HA installation test. CI also runs hassfest and HACS validation after publication.
